# Herdr Engineering Loop (controller skill)

This is one of **six standalone skills** installed by the Herdr Role Pack. Install the full local pack with `install.ps1` (Windows) or `install.sh` (macOS/Linux), then assign exactly one role per Herdr agent through `ROSTER.md` and its generated role packet. The other five skills are `herdr-manager`, `herdr-delegator`, `herdr-worker`, `herdr-verifier`, and `herdr-critic`.

**Workers must be separate Herdr agents, not Codex internal subagents.** The Delegator owns worktree, pane, task, readiness, reports, and integration. If the Delegator is Codex and a Codex worker needs an overridden model/effort, a **Claude Manager** performs only the requested Herdr `agent start`, with a durable `SPAWN_REQUEST`/`SPAWN_READY` receipt. If both leaders are Codex, the override spawn needs a human or explicitly reassigned non-Codex operator. An invalid override blocks `TASK_START`.

Default implementation models: `gpt-6-luna` (`xhigh`, or approved `max`) and `claude-haiku-5-5`; Agy retains its locally configured model and required trusted sandbox safeguards. Optional read-only independent Critic: `claude-sonnet-5-5`, returning `CRITIQUE_READY`. Implementation workers never run tests. A separately assigned Claude Haiku 5.5 agent is the preferred dedicated tester via `herdr-verifier` (not the Worker role); the Delegator can also run trivial checks itself. Only one heavy local verification job may run at a time, even when multiple implementation workers are approved.

Herdr's own CLI skill is available from `herdr --skill` or https://herdr.dev/docs/agent-skill/. This role pack does not install or run the agent CLIs and does not provide native Signals or Relay. Use named `herdr agent prompt` events and durable Markdown; preserve the live Delegator-owned `SESSION.md` when rebinding roles. See `SKILL.md` and `references/model-routing.md`.
